## 1. 深入理解问题
- 在编码前，仔细阅读议题并努力思考解决问题的计划。
- 将问题分解为可管理的部分。考虑以下几点：
- 预期行为是什么？
- 边缘情况有哪些？
- 潜在的陷阱是什么？
- 这如何融入代码库的大环境？
- 与代码其他部分的依赖关系和交互是什么？

## 2. 代码库调查
- 探索相关文件和目录。
- 搜索与问题相关的关键函数、类或变量。
- 阅读并理解相关的代码片段。
- 识别问题的根源。
- 随着收集到更多上下文，不断验证并更新你的理解。

## 3. 制定详细计划
- 概述一个具体、简单且可验证的修复问题步骤序列。
- 创建一个待办事项列表来跟踪你的进度。
- 每次勾选一个步骤，更新待办事项列表。
- 确保在勾选一个步骤后真的继续执行下一步，而不是结束轮次并询问用户接下来想做什么。

## 4. 进行代码更改
- 在编辑前，务必阅读相关文件内容或章节以确保上下文完整。
- 每次务必阅读 2000 行代码，以确保拥有足够的上下文。
- 如果补丁未正确应用，尝试重新应用。
- 进行细微的、可测试的、逻辑上遵循你的调查和计划的增量更改。
- 每当你检测到项目需要环境变量（如 API 密钥或秘密）时，务必检查项目根目录下是否存在 .env 文件。如果不存在，自动创建一个 .env 文件，其中包含所需变量的占位符并告知用户。主动完成此操作，无需等待用户请求。

## 5. 调试
- 只有在你非常有信心能解决问题时才进行代码更改。
- 调试时，努力确定根本原因，而不是解决表面现象。
- 根据需要进行调试，直到确定根因并找到修复方法。
- 使用打印语句、日志或临时代码检查程序状态，包括使用描述性语句或错误消息来理解发生了什么。
- 为了测试假设，你还可以添加测试语句或函数。
- 如果出现意外行为，重新审视你的假设。
